아홉 가지 단서 — 변수 사전

핵심 질문: −1, 0, 1이라는 숫자 뒤에는 어떤 흔적이 숨어 있을까?

데이터의 열 아홉 개는 사이트에 남은 흔적을 숫자로 바꾼 단서(변수)입니다. 이 장에서는 단서를 하나씩 사전처럼 읽습니다. 연구실 식구가 한 단서씩 맡아 "진짜 사이트에서는 어떻고, 가짜 사이트에서는 어떤지" 설명하고, 실제 1,353개 사이트에서 값마다 피싱이 얼마나 섞였는지 셉니다. 끝에서는 설명서와 데이터가 반대 방향인 단서들을 만나고, 단서 하나와 단서 아홉 개가 겨룹니다.

9단서(특성) 수
7값이 세 가지(−1, 0, 1)인 단서
2값이 두 가지인 단서 (도메인 나이 · IP 주소)
0빈 값(결측값)
박사

단서 아홉 개를 세 묶음으로 나눠 볼게요. 페이지가 하는 일, 주소와 신분증, 평판과 나이.

조수 하루

열 이름이 영어 약자라 겁났는데, 하나씩 뜻을 붙이니 읽히기 시작해요.

초파리 연구원

설명서만 믿지 마. 값 1이 "정상"이라고 적혀 있는데, 데이터를 세 보면 반대인 단서가 많아.

주판봇

단서가 아홉이면 아홉 배 정확해지는 거 아냐? 다 넣으면 이기는 판이지!

처음 오신 분께 — 이 장을 3줄로

  1. 무엇을 단서 아홉 개(SFH, popUpWidnow, SSLfinal_State, Request_URL, URL_of_Anchor, web_traffic, URL_Length, age_of_domain, having_IP_Address)의 뜻과 실제 값 분포를 봅니다.
  2. 왜 중요한가 모델은 숫자만 보지만, 사람은 숫자의 뜻을 알아야 결과를 해석하고 잘못을 알아챕니다.
  3. 놀랄 점 설명서는 "1 = 정상 쪽 신호"라고 하는데, 이 데이터에서는 아홉 중 일곱 단서가 1일 때 오히려 피싱이 많습니다(2-4).

단서의 정확한 판정 기준(예: 주소가 몇 글자 이상이면 "길다")은 이 데이터의 UCI 설명서에 적혀 있지 않습니다. 이 장은 기준을 지어내지 않고, 단서의 뜻과 실제 개수만 다룹니다.

값 −1, 0, 1은 어떻게 읽나

하루 −1은 "마이너스 1점"처럼 나쁜 거예요? 더하거나 빼는 숫자예요?

학교 수학으로 보면: 수직선의 −1, 0, +1이 아니라 "세 가지 이름표"

이 숫자들은 크기를 재는 값이 아니라 세 가지 판정에 붙인 번호입니다. 데이터 설명서는 원래 "정상 · 의심 · 피싱"이라는 말을 각각 1 · 0 · −1로 바꿔 적었다고 밝힙니다. 그러니 "1 = 정상 쪽 신호, 0 = 애매함, −1 = 피싱 쪽 신호"로 읽으라는 뜻입니다. 단, 2-4에서 보듯 이 데이터에서 실제로 세어 보면 방향이 반대인 단서가 많습니다.

SFH — 입력 폼이 가는 곳

로그인·회원가입 입력란(폼)에 입력하고 버튼을 누르면, 그 값은 페이지에 적힌 처리 서버 주소로 보내집니다. 이 주소가 비어 있거나 전혀 다른 도메인이면 수상합니다.

진짜 사이트에서는 입력값이 같은 도메인의 서버로 갑니다.
가짜 사이트에서는 처리 주소가 비어 있거나(about:blank 등) 다른 도메인입니다. 입력값을 몰래 다른 곳으로 보냅니다.

값 개수 코드 재현 -1: 445개 · 0: 141개 · +1: 767개

이 데이터에서 실제로 본 것 값 +1인 사이트 767개 가운데 84%가 피싱, 값 −1인 445개 가운데 76%가 정상입니다. 정답과 가장 강하게 함께 움직이는 단서입니다(상관계수 -0.6783).

박사

SFH는 Server Form Handler의 줄임말이에요. "로그인 입력란에 쓴 값을 누가 받아 가느냐"를 보는 단서죠. 피싱의 목적이 바로 그 값을 가져가는 거라서 가장 직접적인 흔적이에요.

popUpWidnow — 팝업 창

사이트가 새 창(팝업)을 띄우는지, 그 창에 입력란이 있는지를 봅니다.

진짜 사이트에서는 팝업을 거의 쓰지 않거나, 써도 공지 정도입니다.
가짜 사이트에서는 팝업 창에 입력란을 띄워 정보를 받아 가려 합니다.

값 개수 코드 재현 -1: 532개 · 0: 639개 · +1: 182개

이 데이터에서 실제로 본 것 값 +1인 182개 가운데 92%가 피싱이고 정상은 0%입니다. 값 0인 639개도 65%가 피싱입니다.

모아

새 창이 자꾸 떠서 "여기에 정보를 입력하세요" 하면 저라도 헷갈릴 것 같아요. 진짜 사이트는 보통 팝업으로 개인정보를 묻지 않는대요.

Request_URL — 외부 그림·영상 비율

페이지에 보이는 이미지·영상·글꼴 같은 재료 가운데 다른 도메인에서 불러오는 것이 얼마나 되는지의 비율입니다.

진짜 사이트에서는 재료 대부분을 자기 서버에서 불러옵니다.
가짜 사이트에서는 진짜 사이트의 로고·그림을 그 사이트 주소에서 그대로 불러와 진짜처럼 보이게 합니다.

값 개수 코드 재현 -1: 617개 · 0: 421개 · +1: 315개

이 데이터에서 실제로 본 것 값 +1인 315개 가운데 83%가 피싱, 의심은 0%입니다. 값 −1과 0에서는 피싱과 정상이 비슷하게 섞여 있습니다.

시아

그림이 어디에서 오는지 세는 단서입니다. 가짜 사이트는 진짜 사이트의 로고와 그림을 그대로 빌려 오는 경우가 많습니다.

URL_of_Anchor — 링크가 가리키는 곳

페이지 속 링크(<a> 태그)들이 다른 도메인이나 빈 링크(#)를 가리키는 비율입니다.

진짜 사이트에서는 메뉴·공지 링크가 대부분 같은 사이트 안의 페이지로 갑니다.
가짜 사이트에서는 링크 대부분이 "#"(아무 데도 안 감)이거나 진짜 사이트로 갑니다.

값 개수 코드 재현 -1: 610개 · 0: 167개 · +1: 576개

이 데이터에서 실제로 본 것 값 +1인 576개의 67%, 값 0인 167개의 59%가 피싱입니다. 값 −1에서는 정상이 55%로 더 많습니다.

하루

<a> 태그는 누르면 다른 곳으로 가는 링크예요. 가짜 사이트는 링크를 그럴듯하게 늘어놓기만 하고, 눌러 보면 아무 데도 안 가거나(#) 남의 사이트로 가요.

일상으로 치면

처음 간 가게에서 계산대가 가게 밖 다른 건물에 있거나(SFH), 직원이 자꾸 따로 불러내거나(팝업), 진열품이 전부 남의 가게 물건이면(Request_URL) 수상합니다.

모델에서는

모델은 "수상하다"는 감각 없이 숫자 조합과 정답이 얼마나 자주 함께 나왔는지만 셉니다. 그래서 단서의 이름표(값의 방향)가 틀려 있어도 배울 수는 있습니다(2-4).

SSLfinal_State — HTTPS 인증서 상태

주소가 https로 시작하는지, 그 인증서를 믿을 만한 기관이 발급했는지, 유효기간이 넉넉한지를 묶어 하나의 값으로 만든 단서입니다.

진짜 사이트에서는 https를 쓰고, 널리 믿는 기관이 발급한 인증서이며, 유효기간도 깁니다.
가짜 사이트에서는 https가 없거나, 처음 보는 발급기관의 인증서이거나, 유효기간이 아주 짧습니다.

값 개수 코드 재현 -1: 308개 · 0: 294개 · +1: 751개

이 데이터에서 실제로 본 것 값 +1인 751개의 74%가 피싱, 값 −1인 308개의 77%가 정상입니다. SFH 다음으로 정답과 강하게 함께 움직입니다(상관계수 -0.5188).

초파리

자물쇠가 있다고 안심하지 마. 요즘은 가짜 사이트도 인증서를 쉽게 받아. 그래서 "누가 발급했나, 언제까지 유효한가"까지 보는 거야.

URL_Length — 주소 길이

주소창 전체 URL의 길이가 의심스러울 만큼 긴지를 본 단서입니다. 길게 늘이면 화면에서 뒷부분이 잘려 보이지 않습니다.

진짜 사이트에서는 짧고 읽기 쉬운 주소를 씁니다.
가짜 사이트에서는 진짜 도메인 이름을 주소 중간에 넣고 뒤에 긴 문자열을 붙여 진짜처럼 보이게 합니다.

값 개수 코드 재현 -1: 431개 · 0: 563개 · +1: 359개

이 데이터에서 실제로 본 것 세 값 모두에서 피싱이 40~60% 섞여 있습니다(+1: 59%, 0: 55%, −1: 42%). 혼자서는 힘이 약한 단서이지만, 값 +1에서 의심 사이트가 16%로 다른 값보다 많습니다.

주판봇

길이는 숫자니까 내 담당! 주소가 길면 그 속에 진짜 사이트 이름을 끼워 넣고 수상한 부분은 뒤로 숨기기 쉽대. 길다고 다 가짜는 아니지만.

having_IP_Address — IP 주소 사용

주소창에 도메인 이름 대신 숫자 IP 주소(예: 198.51.100.23)가 쓰였는지를 본 예/아니오 단서입니다. 0 = 안 씀, 1 = 씀.

진짜 사이트에서는 도메인 이름(www.…)으로 접속합니다.
가짜 사이트에서는 이름 없이 숫자 주소로 접속하게 합니다. 도메인을 등록하지 않아도 되기 때문입니다.

값 개수 코드 재현 0: 1198개 · +1: 155개

이 데이터에서 실제로 본 것 IP 주소를 쓴 사이트는 155개(11%)뿐입니다. 그중 피싱은 59%로, 쓰지 않은 사이트(51%)보다 조금 높을 뿐입니다. 3장에서는 이 값이 "이상치"로 잘못 잡히는 장면이 나옵니다.

하루

인터넷의 모든 서버는 숫자 주소(IP)를 가져요. 보통은 기억하기 쉬운 도메인 이름으로 접속하는데, 주소창에 숫자만 보이면 정식 이름이 없는 사이트일 수 있어요.

설명서와 데이터가 반대?

지표: 상관계수연구실: 설명서 검증

설명서대로라면 단서 값이 1일수록 정상(Result = 1)이 많아야 합니다. 그러면 단서와 정답의 상관계수는 양수(+)가 나와야 합니다. 실제로 계산해 보면 아홉 중 여덟이 음수이고, 양수는 web_traffic 하나뿐입니다. having_IP_Address(0/1 = 아니오/예)는 뜻이 다르게 매겨진 단서라 따로 봅니다.

실험 · 단서와 정답의 상관계수 코드 재현

상관계수를 처음 보는 분께

하루 −0.68이 "아주 반대"라는 건 알겠는데, 정확히 무슨 뜻이에요?

학교 수학으로 보면: 두 줄의 숫자가 "같이 오르내리는 정도"를 −1~+1로 줄인 값

한 단서의 값이 클 때 정답도 크면 +쪽, 단서가 클 때 정답이 작으면 −쪽입니다. 0 근처면 거의 관계없습니다. 정답 숫자는 1 정상, 0 의심, −1 피싱이므로, 음수 = 단서 값이 클수록 피싱 쪽이라는 뜻입니다.

숫자로 읽어 보기
SFH의 상관계수 -0.6783 → SFH가 클수록 정답이 작다(피싱 쪽) → 실제로 SFH = +1인 사이트의 84%가 피싱
web_traffic의 상관계수 +0.2439 → 클수록 정상 쪽 → 실제로 web_traffic = +1인 사이트의 53%가 정상

상관계수는 두 값이 함께 움직이는 정도일 뿐, 원인과 결과를 뜻하지 않습니다. 또 이 정답 숫자(−1, 0, 1)는 크기가 아니라 이름표라서, 상관계수는 방향을 보는 데만 씁니다.

풀이

  1. 설명서의 "1 = 정상 신호"를 따르면 상관계수가 양수여야 하는데, web_traffic 말고는 모두 음수입니다.

  3. 분석의 원칙: 설명서는 가설이고, 해석 전에 데이터로 확인합니다. 이 장의 모든 "가짜 사이트에서는" 설명은 단서의 뜻이고, 숫자는 실제 개수입니다.
